# v0.15.0 — List the streams under a scope

> Draft release notes, kept in the repo so the upgrade lands with the release. The
> published release page is assembled from this file (`docs/agents/release.md`).

## Highlights

**You can find every stream under a scope.** A scoped hard delete (every stream of one
tenant or catalog) had to discover its stream ids from your own read models, which misses
stream types that have none. `PostgresEventStore::stream_ids(scope, after)` lists the ids
across **all** stream types, compacted streams included, in bounded chunks of at most 256
ids, releasing its connection before it yields. You can delete a page while reading the
next, even with a one-connection pool (replay#295).

None. The release is additive: no signature changed, no migration, no behaviour change.

## New API

### `PostgresEventStore::stream_ids`

```rust
pub fn stream_ids(
    &self,
    scope: StreamScope,
    after: Option<Urn>,
) -> impl futures::Stream<Item = Result<Urn, replay::Error>> + Send + 'static
```

List a page of a catalog's streams with `.take(n)`, hard-delete it, then resume with
`after`:

```rust
use futures::{StreamExt, TryStreamExt};
use replay_persistence::StreamScope;

let mut after: Option<Urn> = None;
loop {
    let page: Vec<Urn> = store
        .stream_ids(StreamScope::within(&branch_id), after.clone())
        .take(100)
        .try_collect()
        .await?;
    let Some(last) = page.last().cloned() else { break }; // an empty page ends the pass

    store
        .delete_streams(&page, |conn, ids| {
            Box::pin(async move {
                let ids: Vec<String> = ids.iter().map(Urn::to_string).collect();
                sqlx::query("DELETE FROM bank_account_balances WHERE stream_id = ANY($1)")
                    .bind(&ids)
                    .execute(&mut *conn)
                    .await
                    .map_err(replay_persistence::db_error)?;
                Ok(())
            })
        })
        .await?;

    after = Some(last); // resume even though these ids are now deleted
}
```

- `StreamScope::within(&branch_id)` is `StreamScope::Suffix("@branch:…".into())` for
  that id and includes nested ids; `Prefix` and `All` also exist. `%`, `_` and `\` match
  literally.
- Ids follow the `streams.id` collation, not `Urn`'s `Ord`. `after` is exclusive; `None`
  starts at the beginning.
- A suffix filter has no index: each chunk scans forward from the cursor until 256 matches
  or the end, so the chunk bounds the ids returned, not the rows examined.

**It is not a snapshot, and not an atomic scope deletion.** Concurrent inserts behind the
cursor, recreated ids included, may be missed, and a listed stream may disappear before you
delete it. For a complete scope hard-delete, coordinate writers, then list again from `None`
to confirm the scope is empty. Follow the hard-delete runbook in the README
([Deleting streams](https://github.com/funkode-io/replay/blob/v0.15.0/README.md)) and the
`0.14.0` rollout rule: `delete_streams` only once every Policy runner and inline projection
process runs `0.14.0` or later.
